# M3 智能识别与混合剪贴板验证

M3 使用窗口获焦和显式智能粘贴两条通路；无后台剪贴板监听、轮询或历史存储。`ToolSession`、检测快照、摘要和接力结果仅驻内存。M4 工厂通过 `ToolViewContext.session` 在创建时读取 `launch_input`，并观察实体通知以接收后续注入；编辑时更新 `input`，运算后发布 `output` 与 `sensitive_output`，供防覆盖、复制和单跳接力统一使用。

## 平台读取与标记

- Windows：同一次 `OpenClipboard` 锁期间，先检查隐藏格式与 `CanIncludeInClipboardHistory` DWORD，随后按文件、PNG/DIB、UTF-16 文本优先级读取。`GlobalSize`、文件数量和路径长度在分配 Rust 缓冲区前检查。写入使用 arboard 3.7 的 monitoring/history 排除标记。
- macOS：先读取类型列表并检查 Concealed/Transient/AutoGenerated/1Password 标记，再读取文件 URL、编码图片或文本；按字节和文件数限制复制进 Rust 内存，结束时验证 `changeCount`。敏感复制附 ConcealedType 与 TransientType。NSPasteboard 本身可能分配数据对象，应用不解码图片为像素。macOS 15.4+/26 的用户手势识别和零弹窗降级须真机验证。
- Linux X11：x11rb 请求 TARGETS 和 KDE 隐藏提示后才请求正文；限制属性大小，INCR 大载荷拒绝读取，核对选区 owner。仅对本次选择转换请求等待通知，不订阅剪贴板变化。
- Linux Wayland：调用系统 `wl-paste` 先查询 MIME 类型与隐藏提示，再有界读取；外部读取设 300 ms 超时。不支持 data-control 或未安装 wl-paste 时返回不可读取，不转到未验证隐藏标记的 XWayland/GPUI 读取路径。

## M5 Linux 真机验收项（已知上游限制）

锁定的 `gpui-pre-linux 0.3.14` 的 Wayland `DataOffer.mime_types` 是私有字段，`App::read_from_clipboard[_async]` 只暴露已读取的 `ClipboardItem`，不公开正文前的 MIME/密码管理器元数据检查，也没有有界原始文件/图片读取契约。直接使用该 API 会破坏零读取护栏。因此本里程碑保留安全失败路径，经实施主线程确认，不绕过隐私检查。

M5 必须在 GNOME/KDE/Sway、X11/Wayland 上确认：wl-paste 可用性、隐藏内容零读取、敏感写入 KDE secret 标记、文件/图片/文本优先级，以及原生中文 IME。GNOME Mutter 无 data-control 时智能粘贴当前也会安全失败；要实现规格要求的 GPUI 获焦降级，需要上游提供 guarded raw clipboard snapshot/MIME preflight 接口（或经审批调整 GPUI 锁版）。不能仅在读完 GPUI 正文之后再判断隐藏标记。

## 本机验证

Windows 11 / Rust 1.98。所有 Cargo 门禁均通过 PowerShell 执行，设置 `$ErrorActionPreference = 'Stop'` 与 `$PSNativeCommandUseErrorActionPreference = $true`：

- `cargo fmt --all -- --check`
- `cargo clippy --workspace --all-targets -- -D warnings`
- `cargo test --workspace`
- `cargo tree -p devtools-core -p devtools-detect -p devtools-tools -p devtools-search -p devtools-platform`：底层无 gpui/tokio，detect 不依赖 tools。
- `cargo deny check`：advisories、bans、licenses、sources 四项通过。现有重复版本/未命中 advisory ignore 警告不阻断；ksni Unlicense 和 nucleo-matcher MPL-2.0 均保留精确包级例外。
- `cargo build --workspace`

本机未安装 macOS/Linux Rust target，未宣称完成三端原生编译或真机 GUI 验收。UI 仍使用 M2 工具计算占位视图；M3 已接通内存会话和输出接力接口，实际计算按 V1 路线留给 M4。
