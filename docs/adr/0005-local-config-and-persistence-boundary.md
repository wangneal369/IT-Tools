# 采用 TOML 壳层配置、损坏隔离回退与「零工具载荷落盘」持久化边界

V1 本地状态采用 **`directories` + 平台标准用户配置目录**（限定符 `io.github.wangneal369.devtools`）下的 **`config.toml`（`schema_version = 1`）** 与并列的 **`window-state.toml`**，仅持久化壳层偏好、收藏顺序、全局快捷键、常驻行为、智能识别开关与窗口几何；**`最近使用` 与全部 `标签会话` 内容仅驻进程内存**，彻底退出即清空。默认冷启动只恢复壳层偏好并打开工作台首页；可选「退出时记住已打开工具标签」**仅持久化有序 `ToolId` 列表、重启为空标签实例**。配置损坏时将主文件重命名为 `config.toml.invalid-<timestamp>` 并以默认配置冷启动，同时在设置页一次性提示。设置变更按域分级热生效（外观/智能识别/窗口语义立即；全局热键与开机自启保存时注销重注册，失败回滚 UI）。选用该边界是因为 [ADR-0002](0002-two-stage-headless-background-residency.md) 与 [ADR-0003](0003-focus-triggered-hybrid-smart-detection.md) 已将敏感工作现场与剪贴板管线锁定在内存态，任何 session 序列化或跨重启 Recents 都会正面违反零遥测、零剪贴板历史与密码管理器零读取的产品红线，且日后难以在无迁移痛苦下撤回。

## Considered Options

- **JSON 单文件或 SQLite 本地库承载工具草稿/会话**：便于崩溃恢复与跨重启续作，但无法从架构上证明用户敏感输入未落盘，且与「彻底退出清空现场」语义冲突，排除。
- **跨重启持久化 `最近使用` 列表**：仅 ToolId 看似低敏，但会构成可推断使用轨迹的持久日志，与 Recents「非历史管理器」定位不符，排除。
- **损坏配置静默删除字段或部分合并**：会在未知缺失键下产生不可预测行为，排除；改用具名备份 + 默认冷启动。

## Consequences

- **`devtools-core` 需提供可测试的 `Settings`/`WindowState` 模型与显式持久化白名单**，禁止对 `TabSession` 或剪贴板指纹结构实现 `Serialize` 写盘路径（以单测/编译门闩守线）。
- **设置 UI 须标注每项为「立即生效」或「保存后重新注册」**；热键/自启注册失败不得留下与 OS 不一致的勾选态。
- **可选标签骨架恢复与收藏/托盘二级菜单共享同一有序 `ToolId` 源**，但不恢复各标签页的输入、输出与局部选项。
